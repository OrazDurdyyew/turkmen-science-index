# Roadmap: TSI MVP

> Статус на 2026-10-25: этапы 1–7 выполнены, кроме графа цитирований (опционально). Сверх плана: профили авторов без аккаунта и заявки «Это я», массовый импорт PDF, продакшен-сборка фронтенда.

## Этапы разработки

### Этап 1: Фундамент (Неделя 1-2)
> Цель: рабочая БД + авторизация + базовый UI

- [x] Инициализация Supabase проекта (`supabase init`)
- [x] Применение SQL-миграции (DATABASE_SCHEMA.md → `001_initial_schema.sql`)
- [x] Настройка Supabase Auth (email + password)
- [x] Инициализация Nuxt 4 проекта
- [x] Подключение Supabase JS SDK
- [x] Базовые страницы: регистрация, вход, главная
- [x] Настройка Tailwind CSS + базовый layout

**Зависимости:** нет
**Результат:** пользователь может зарегистрироваться и войти

---

### Этап 2: Данные и профили (Неделя 3-4)
> Цель: CRUD для статей и профилей авторов

- [x] Страница профиля автора (просмотр)
- [x] Редактирование своего профиля (ФИО, ВУЗ, ORCID)
- [x] Ручное добавление статьи (форма: заголовок, аннотация, журнал, дата)
- [x] Справочник журналов (CRUD для админа)
- [x] Привязка авторов к статье (M2M через publication_authors)
- [x] Страница статьи с метаданными

**Зависимости:** Этап 1
**Результат:** можно добавлять статьи вручную и видеть профили авторов

---

### Этап 3: PDF Parsing (Неделя 5-6)
> Цель: автоматическое извлечение данных из PDF

- [x] Docker Compose: GROBID контейнер
- [x] FastAPI сервис: эндпоинт POST /parse
- [x] Интеграция с GROBID API (отправка PDF, получение TEI XML)
- [x] Парсинг TEI XML → метаданные (заголовок, авторы, аннотация)
- [x] Парсинг списка литературы → raw_references
- [x] Загрузка PDF в Supabase Storage
- [x] UI: страница загрузки PDF с предпросмотром результатов
- [x] ~~Edge Function: триггер на загрузку~~ → фронтенд вызывает парсер напрямую с токеном пользователя (проще, без лишнего звена)

**Зависимости:** Этап 2
**Результат:** загрузил PDF — получил статью с метаданными и сырыми ссылками

### Этап 4: Matching + Citations (Неделя 7-8)

**Зависимости:** Этап 3
**Результат:** система автоматически связывает цитирования и считает h-index

**Зависимости:** Этап 4

## Приоритеты

```
Критично (MVP)          Важно (v1.1)           Будущее (v2)
─────────────           ────────────           ────────────
SQL-схема               Импакт-фактор          ИИ matching
Auth + профили          Экспорт (BibTeX)       ORCID OAuth
Загрузка PDF            Bulk upload            API для ВУЗов
GROBID парсинг          Уведомления            Мобильное приложение
Fuzzy matching          Рейтинги ВУЗов         Международная интеграция
h-index расчёт          Статистика/графики      DOI registration
Полнотекстовый поиск    Расширенная админка    Рецензирование
Админ-панель (базовая)
```

## Технические решения по этапам

| Решение | Этап | Обоснование |
|---------|------|-------------|
| Supabase вместо custom backend | 1 | Быстрый старт, Auth/Storage из коробки |
| Ручной ввод статей до парсинга | 2 | Можно тестировать UI без GROBID |
| GROBID в Docker | 3 | Изоляция, воспроизводимость |
| pg_trgm вместо ML | 4 | Достаточно для MVP масштаба |
| Cron вместо realtime для h-index | 4 | Оптимизация производительности |
